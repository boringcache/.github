# Contributing to BoringCache

Thank you for taking the time to improve BoringCache.

## Support and issue reports

- Use [support@boringcache.com](mailto:support@boringcache.com) for account,
  workspace, billing, or product support.
- Report vulnerabilities privately according to the
  [security policy](https://boringcache.com/security).
- Use a repository issue for a reproducible bug, documentation correction, or
  focused feature proposal concerning that public repository.

Read the repository README before opening an issue or pull request. Some
repositories distribute binaries or images. For a non-trivial change, open an
issue first so maintainers can confirm the scope and contribution process.

## A useful issue

Please include:

- the BoringCache version or immutable Action/image reference;
- operating system, architecture, CI provider, and relevant tool versions;
- the command or minimal workflow that failed;
- expected and actual behavior; and
- scrubbed logs or diagnostics that help reproduce the problem.

Do not include access tokens, credentials, private repository content, customer
data, or signed storage URLs.

## A useful pull request

Keep the change focused and explain the user-visible outcome. Add or update the
smallest meaningful tests and documentation. Follow the contribution instructions in the repository, and keep unrelated
cleanup in a separate change.

By contributing, you agree that your contribution is licensed under the license
of the repository receiving it. Participation is governed by the
[BoringCache Code of Conduct](https://github.com/boringcache/.github/blob/main/CODE_OF_CONDUCT.md).
